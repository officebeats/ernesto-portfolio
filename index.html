Featured Work

The Ascension multi-agent system.

Healthcare · 2025 A2A Protocol Multi-Agent Orchestration Production Shipped Ascension Health

The Problem

Ascension Health needed a consumer-facing AI system capable of understanding patient intent and intelligently routing to specialized sub-agents — each built by different teams across different platforms — while enforcing consistent business rules throughout the interaction.

My Role

As PM, I owned the requirements and architecture decisions for the Steering Agent — the consumer-facing orchestration layer at the top of the agent hierarchy. I was also responsible for defining all agent cards across the system and aligning cross-functional teams on a unified implementation approach.

Approach

Selected and defined the A2A (Agent-to-Agent) protocol as the interoperability standard — establishing typed capability contracts between the Steering Agent and every sub-agent in the network. Collaborated with 3+ teams building agents on disparate platforms and the enterprise architecture team to validate the protocol selection and handoff design. Designed the full routing logic: how user intent is parsed, which business rules govern sub-agent assignment, and what fallback and escalation paths exist.

Outcome

A production multi-agent system shipped at one of the largest health systems in the US. Grace AI, the appointment management sub-agent I also defined, went live as part of this system — handling patient appointment cancellations and verifications end-to-end. This was not a chatbot. It was a distributed agent network with typed contracts, capability declarations, and protocol-level handoffs between agents built by independent teams.

Point of View

My take on
agentic AI.

Agents need contracts before code.

Agent cards, A2A handoff protocols, and capability boundaries must be defined before prompts are written. Ambiguous agent design produces unpredictable production behavior — and that's a PM failure, not an engineering one.

The PM owns the agent's judgment calls.

Every routing decision, every fallback, every escalation path is a product decision. I treat agent behavior like any critical user flow: intentional, tested, and owned end-to-end.

Human-in-the-loop is a feature, not a fallback.

Designing when and how an agent hands off to a human is as important as the agent workflow itself. The best agentic products make that handoff feel invisible — and that's entirely a product design problem.
